The Fabric of the Internet

Why Is It
Built This Way?

Decentralized · Addressed · Redundant

Think About It

  • The Internet has no central control computer.
  • To connect a billion devices, why NOT just wire everyone to everyone?
There's a mathematical reason.

The Cost of Connecting Everyone

To fully connect n devices you need n(n-1)/2 links.
10 devices → 45 links 50 devices → 1,225 links 1,000 devices → 499,500 links
Full connection is O(n²) — impossible at scale.

The Fix: Shared Routing

Instead of connecting everyone directly, devices share routes through ROUTERS. Adding a device adds ~1 link, not n.
DEVICE → ROUTER → ROUTER → DEVICE

Addressing
& Routing

IP · Next Hop

Every Device Has an Address

An IP address is a unique numeric identifier. Routers use the destination IP + a routing table to pick the NEXT HOP.
Like a postal system choosing the next sorting center.

Reading a Routing Table

Ava's Phone 192.168.2.2 → Router C Ryan's Laptop 192.168.2.1 → Router D Mia's Tablet 192.168.1.2 → Router A
Trace the path: destination IP decides the next hop.

Redundancy = Fault Tolerance

Multiple paths mean the network survives failures. A SINGLE POINT OF FAILURE is a component whose loss disconnects part of the network.
Find it. Remove it. Add a backup path.

Packets

Data is split into small numbered packets. They may take different routes and arrive out of order — numbering lets the receiver reassemble them.
Lost one? Acknowledge + resend just that packet.

Protocols

TCP vs UDP

The Reliability / Speed Tradeoff

  • TCP — guarantees delivery + order. Web, email, files. Costs speed.
  • UDP — fast, no guarantees. Live video, voice, gaming.
Pick based on what failure you can tolerate.

Which Would You Use?

  1. A live esports stream?
  2. Downloading a game update?
  3. A bank transfer?
Justify each with the tradeoff.

Design a Reliable Network

Design a network for a context YOU choose — home, school lab, a business you'd start, an esports team across cities. Address it, route it, make it redundant, and label TCP vs UDP.
Details on your worksheet.

Try to Break It

Swap designs. Hunt for a single point of failure your partner missed.
The best networks survive any one failure.

Reliable by design,
not by luck.
