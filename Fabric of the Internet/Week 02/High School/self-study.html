Lesson 1

DNS: Names to Addresses

You type example.com, but computers route by numbers — IP addresses. The Domain Name System (DNS) is the Internet's phone book: it turns human-friendly names into machine addresses. And it's not one giant list on one server — it's a distributed hierarchy, so no single machine has to know every name on earth.

Your resolver — the machine that asks around

Your device sends the name to a resolver (often run by your ISP or a service like 1.1.1.1). Its job is to hunt down the answer on your behalf, step by step.

Root & TLD — narrowing it down

The resolver asks a root server, which points it to the right TLD server for the ending — .com, .org, .edu. Each step narrows the search instead of scanning everything.

Authoritative server — the final answer

The TLD points to the domain's authoritative server, which returns the actual IP address. Now your browser knows where to connect.

The demo on the right resolves a domain name to an IP by looking it up in a DNS table.

Lesson 2

HTTP: Request & Response

DNS gets you the address. Now the browser actually talks to the server using HTTP. It's a simple conversation: the browser sends a request (a method like GET plus a path), and the server sends back a response — a status code plus the page.

You've met these status codes without knowing it: 200 OK (here's your page), 404 Not Found (that page doesn't exist), 500 Server Error (something broke on their end).

A tiny HTTP exchange

> GET /about.html HTTP/1.1
> Host: example.com

< HTTP/1.1 200 OK
< Content-Type: text/html
<
< <html>...the page...</html>

Request goes up (>), response comes back (<). Same pattern behind every page you load, every image, every API call.

Stuck? Example edit

Add your own site by putting a new entry in the dnsTable in index.js, then point lookup at it:

var dnsTable = {
  "example.com": "93.184.216.34",
  "school.edu": "192.0.2.10",
  "mygame.io": "203.0.113.7",
  "myfavesite.com": "198.51.100.42"   // <- your site
};

var lookup = "myfavesite.com";

To print the TLD, grab the part after the last dot with split('.').pop():

var tld = lookup.split(".").pop();   // "com"
out.textContent += "\nTLD: ." + tld;

Try a name you never added — like "nope.xyz" — and the output should report NXDOMAIN.

Reason About It

Reason About a Dilemma

Here's the twist. The technical Internet is neutral — a router doesn't care whether a packet carries homework, a protest, or a cat video. But the human Internet is full of dilemmas, because access and control aren't shared equally: net neutrality (should ISPs be allowed to speed up or slow down some traffic?), the digital divide (who gets fast, affordable access — and who doesn't?), censorship (who decides what you can reach?), and privacy (who gets to watch what you do?).

Pick one dilemma you actually care about and build a mini-argument. A good argument has a clear claim, real evidence, and an honest answer to the other side.

Wrap-Up

The Big Idea

DNS + HTTP turn a name into a page in milliseconds — a name becomes an address, an address becomes a request, a request becomes the page in front of you. But the hardest Internet questions aren't technical; they're about fairness, access, and power: who gets on, who gets fast lanes, who gets watched, who gets to decide.

Keep going: next time you hit a slow site, a paywall, a blocked page, or a "no service here," ask who benefits from it working this way? — that's the question an engineer and a citizen both need.
