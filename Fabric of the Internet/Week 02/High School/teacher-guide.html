The Web & the Dilemmas It Creates

Week 2 — DNS, HTTP, net neutrality, the digital divide, and a reasoned position

At a Glance

Driving Question
How does the web actually fetch a page — and what dilemmas does a global, unequal Internet create?
Big Idea
DNS resolves names to addresses through a hierarchy, and HTTP is a request/response protocol that fetches resources. But the Internet raises hard dilemmas — net neutrality, the digital divide, censorship, privacy — that have no purely technical answer.
Schedule
Day 1 Learn (45 min) · Day 2 Explore (90 min) · Day 3 Create (90 min)
Week Deliverable
An Internet Dilemmas position paper/presentation: a claim on a student-chosen dilemma, defended with network principles + real evidence

Learning Objectives

Students will be able to:

  • Explain how DNS resolves a domain name to an IP address through a hierarchy (resolver → root → TLD → authoritative)
  • Describe the anatomy of an HTTP request/response (method, path, status code) and how it fetches resources
  • Interpret real data on the digital divide and explain net neutrality with precision
  • Construct and defend a reasoned position on an Internet dilemma using evidence and network principles

Day 1 — Learn: How the Web Fetches a Page

DNS resolution and the HTTP request/response cycle

Time Activity
0–6 min Hook — "What happens between typing a name and seeing the page?"
6–22 min Mini-lesson — DNS hierarchy + HTTP request/response anatomy
22–38 min Trace a real request — DNS resolution walkthrough + inspect an HTTP request
38–42 min Optional enrichment (Internet Simulator) + share-out
42–45 min Exit ticket

Hook (6 min)

"You type a domain name and a page appears. Between those two moments, your computer does a hierarchical lookup and a request/response conversation with a server on the other side of the world. Let's open the hood."

Give students 90 seconds to write down every step they think happens between pressing Enter and seeing the page. Collect a few guesses on the board — you'll return to this list at the exit ticket and let them correct it. The gap between their intuition and the real sequence is the lesson.

Mini-lesson: DNS Hierarchy + HTTP Anatomy (16 min)

"A domain name like example.com is for humans. The network routes to numeric IP addresses. DNS is the system that translates one into the other — and it does it through a hierarchy, not one giant phone book. Then HTTP takes over to actually fetch the page. Let's define the pieces precisely."

  • DNS — Domain Name System: a distributed, hierarchical system that resolves domain names to IP addresses.
  • DNS RESOLVER — the service your device asks first; it queries other servers on your behalf and caches the answer.
  • ROOT / TLD / AUTHORITATIVE — the hierarchy: the root points to the TLD server (.com, .org), which points to the authoritative server that holds the domain's actual IP.
  • HTTP — HyperText Transfer Protocol: a request/response protocol for fetching resources.
  • HTTP METHOD / STATUS CODE — e.g., GET requests a resource; 200 = OK, 404 = Not Found, 500 = server error.

"Walk it end to end. Your browser asks the RESOLVER for example.com. The resolver asks a ROOT server, which says 'ask the .com TLD server.' The TLD server says 'ask example.com's AUTHORITATIVE server.' That server returns the IP. Now the browser opens a connection to that IP and sends an HTTP GET request. The server replies with a status code and the page. Name resolved, resource fetched."

"Here's what that HTTP conversation actually looks like on the wire — a request from your browser, and the first line of the server's response."

# Request your browser sends GET /index.html HTTP/1.1 Host: example.com # Response the server sends back HTTP/1.1 200 OK Content-Type: text/html

Non-CS teachers: the whole DNS idea is "ask someone who knows someone who knows the answer." Root → TLD → authoritative is just narrowing down: continent → country → street address. HTTP is even simpler — it's a request ("please send me this") and a response ("here it is, status 200" or "can't find it, 404").

Open the Hood (16 min)

"Live demo — open your browser's DevTools → Network tab, load a page, and let's watch the requests appear. Look at the method (GET), the path, and the status code on each one. Optionally I'll run nslookup example.com in a terminal to show DNS returning an actual IP address."

  • Right-click → Inspect → Network tab, then reload. Point out that one page is dozens of separate requests — HTML, CSS, images, scripts — each with its own status code.
  • Filter to a single request and show the request headers (Host, method) and the response status. Connect each field back to the vocab.
  • Keep it a demo. Students replicate the sequence conceptually on the worksheet — they diagram the DNS resolution path and label a request/response, no login or setup required.

If a device blocks DevTools, the worksheet stands alone: students order the resolution steps and annotate the sample HTTP exchange above. The concept is the target, not the tooling.

Optional Enrichment + Share-Out (4 min)

CSP Unit 2's HTTP and DNS lessons use the Internet Simulator to watch requests travel — entirely optional, no login required, and the day is complete without it.

Code.org · CS Principles Unit 2 (HTTP/DNS, optional)

In sequence, list what happens from typing a domain name to seeing the page. Name DNS's role and HTTP's role.

Every student can sequence DNS resolution and describe an HTTP request/response with a method + status code.

Day 2 — Explore: An Unequal Internet

The digital divide, net neutrality, and the dilemmas they create

Time Activity
0–5 min Warm-up — "Who gets fast access, and who decides what travels fastest?"
5–20 min Mini-lesson — digital divide + net neutrality, defined precisely
20–45 min Data analysis — pull and quantify gaps from Pew
45–70 min Dilemma stations — structured positions on four dilemmas
70–85 min Make It Yours — pick + frame YOUR dilemma
85–90 min Record vocab

Warm-Up (5 min)

"The technical Internet treats all packets similarly — but the human Internet is deeply unequal. Who gets fast, reliable access, and who decides what travels fastest?"

Mini-lesson: Digital Divide + Net Neutrality (15 min)

"Last week you saw the Internet is engineered to treat packets fairly evenly. That's the technical layer. Today we look at the human layer, where access and control are anything but equal. Two terms anchor the whole conversation — let's define them precisely so you can argue with them later."

  • DIGITAL DIVIDE — the gap between those with reliable, high-quality Internet access and those without, and its downstream effects on education, employment, healthcare, and civic life.
  • NET NEUTRALITY — the principle that ISPs should treat all traffic equally, without blocking, throttling, or paid prioritization.

"Notice the tension in each. Net neutrality protects equal access, but it constrains ISP business models — some argue paid 'fast lanes' would fund network build-out. And treating access as a utility that everyone deserves collides with treating it as a market good sold to whoever can pay. There's no formula that resolves these. That's what makes them dilemmas."

Data Analysis: The Divide in Numbers (25 min)

"Analyze real data. On your worksheet, pull specific comparisons from the Pew broadband data — home broadband adoption by income, by community type (urban/suburban/rural), and by age. Then quantify the gap: put an actual number on it."

Pew Research · Internet & Broadband Fact Sheet

Push for numbers — "what's the percentage-point gap between the highest and lowest group, and what does that mean for a student trying to do homework?" A gap you can name is a gap you can argue about; "some people have worse Internet" is not evidence.

Dilemma Stations: Structured Positions (25 min)

"Consider four dilemmas. For each, there are reasonable arguments on multiple sides — your job isn't to pick the 'right' answer, it's to understand why smart people disagree."

  1. Net neutrality — should ISPs be allowed to charge for faster lanes?
  2. The digital divide — is Internet access a right that governments must guarantee?
  3. Censorship & access — should any content be blocked, and who decides?
  4. Privacy — should ISPs be allowed to collect and sell browsing data?
  • Have students take a tentative position on each with one reason and one counter-argument — both, every time.
  • Rotate small groups through the four, or run them as whole-class discussion; the worksheet captures a position + reason + counter for each.

Make It Yours: Frame Your Dilemma (15 min)

"Choose the dilemma you most want to argue — one of these four, or another Internet dilemma you care about: screen-time policy, AI-generated content, misinformation, or access in your own community. Write your working claim and name who is affected."

Encourage a dilemma with personal or local stakes — their own community's access, a platform they actually use. Ownership sharpens the argument: students defend a position harder when it's genuinely theirs, not one they were assigned.

Record Vocab (5 min)

  • DNS resolver
  • HTTP method
  • Status code
  • Digital divide
  • Net neutrality

Every student quantified a digital-divide gap and framed a working claim for their chosen dilemma.

Day 3 — Create: Internet Dilemmas — Take a Position

Build and defend a reasoned argument

Time Activity
0–5 min Launch — "Build a position, not just an opinion"
5–30 min Research + build the argument (claim, evidence, reasoning, counter-argument)
30–55 min Draft the position (paper or slides)
55–72 min Structured peer review
72–88 min Present / defend
88–90 min Reflection

Launch (5 min)

"Today you build a reasoned POSITION on your dilemma — not just an opinion. A strong position has a clear claim, real evidence, network principles to back it, and an honest counter-argument you actually address."

Build the Argument (25 min)

"On your worksheet, assemble four parts. Your CLAIM. At least two pieces of EVIDENCE — data or a documented example. Your REASONING connecting the evidence to the claim, using what you know about how the Internet actually works. And the strongest COUNTER-ARGUMENT against you — which you then rebut."

  • The reasoning is where network principles earn their place: a claim about fast lanes should invoke how routing and prioritization actually work, not just "it feels unfair."
  • Require the counter-argument to be the strongest one, stated fairly — not a strawman that's easy to knock down.

Draft the Position (25 min)

"Write it as a one-page position paper OR a short slide deck. Cite your evidence — where each number or example came from."

Offer format choice: a one-page paper, a short slide deck, or a recorded two-minute argument. The rigor is in the reasoning, not the format — let students pick the medium they'll do their best thinking in.

Structured Peer Review (17 min)

"Trade with a partner. First, STEELMAN their argument — restate it in its strongest possible form, so they know you understood it. Then identify the weakest link and name one specific way to strengthen it."

Present / Defend (16 min)

"Each of you delivers a 60–90 second version of your position, then takes one challenge question from the class. Defending your reasoning out loud is where you find out how solid it really is."

Extend Beyond the Classroom

Encourage students to share their position where it could actually matter — a school policy discussion, a letter to a representative, a community forum, a post. A real audience raises the stakes and turns a school assignment into something with a purpose.

Reflection (2 min)

"Reflection: Why does this dilemma matter to YOU personally? Did building the argument change your own view at all — and if so, how?"

DNS resolution sequence (correct order)

browser → resolver → root → TLD → authoritative → IP returned → browser sends HTTP GET → server returns status + page. The root/TLD/authoritative steps narrow from "which registry" to "which domain's own server."

Common HTTP status codes

200 OK (success) · 301/302 (redirect — resource moved) · 404 Not Found (no such resource) · 500 (server error). A GET requests a resource; the status code reports what happened.

Sample claim — weak vs. strong

Weak: "Net neutrality is good." (Not arguable, no reasoning.) Strong: "ISPs should be barred from paid prioritization because tiered access widens the digital divide for low-income students, as shown by [data]." (Clear, sourced, reasoned.)

The dilemma positions have NO single correct answer. Grade on the QUALITY of the claim, evidence, reasoning, and counter-argument — not on which side the student takes. A well-argued position you disagree with earns full marks.

Every student produced a reasoned position — claim, evidence, network-grounded reasoning, and a rebutted counter-argument — plus an honest, personal reflection.

Additional Notes for the Teacher

Differentiation

  • Support: Provide a claim / evidence / reasoning / counter-argument graphic organizer plus sentence frames ("I claim ___ because ___. Some would argue ___, but ___."); allow a single well-supported argument rather than two pieces of evidence.
  • Advanced: Require rebutting two counter-arguments, comparing how different countries approach the dilemma, or connecting the position to a specific piece of legislation or regulation — and let students push their own chosen direction further.
