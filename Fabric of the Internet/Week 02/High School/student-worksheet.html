Reference

Key Vocabulary

  • DNSDomain Name SystemA distributed, hierarchical system that resolves domain names to IP addresses.
  • DNS ResolverThe service your device asks first; it queries other servers on your behalf.
  • Root / TLD / AuthoritativeThe DNS hierarchy: root → TLD (like .com) → the authoritative server holding the domain's IP.
  • HTTPHyperText Transfer ProtocolA request/response protocol for fetching resources.
  • HTTP MethodThe action a request asks for — e.g. GET requests a resource.
  • Status CodeA short number the server returns: 200 OK, 404 Not Found, 500 server error.
  • Digital DivideThe gap between those with reliable, high-quality access and those without.
  • Net NeutralityThe principle that ISPs treat all traffic equally — no blocking, throttling, or paid prioritization.
Trace It

DNS Resolution Walkthrough

When you type a domain name, DNS resolves it to an IP through a hierarchy. Follow the order below.

Resolution order — reference (do not edit)
  1. Browser asks the resolver.
  2. Resolver asks a root server.
  3. Root points to the TLD server (.com / .org).
  4. TLD points to the authoritative server.
  5. Authoritative returns the IP.
  6. Browser sends an HTTP request to that IP.
In your own words, why is DNS organized as a hierarchy instead of one giant list?
