# Pacing Calendar — Problem Solving & Computing

## Semester Arc Position: **Problem Solving** (the foundation phase)
> Problem Solving → Programming → AI/ML → Cybersecurity → Global Impacts → Capstone

This is the opening unit of the year. Before students write a line of code, they build the *thinking* that all computer science depends on: a repeatable process for solving problems, and a mental model of what a computer actually is. Everything later in the year — apps, AI, security — is an application of these two ideas.

**Approach:** Original content (replaces Code.org). Built from the Problem Solving & Computing deck + Lesson 3 activities + Lesson 8 project.

**Versions:** Middle School (scaffolded, beginner) and High School (more text-based, independent, technical). Files live in `Week ##/Middle School/` and `Week ##/High School/`.

**Schedule:** 1×45 min (Learn) + 2×90 min (Explore, Create) = 225 min/week.

---

## The Weekly Rhythm: Learn → Explore → Create

| Day | Length | Purpose | Shape |
|-----|--------|---------|-------|
| **Day 1 — Learn** | 45 min | Introduce the big idea | Hook · mini-lesson · discussion · quick practice · exit ticket |
| **Day 2 — Explore** | 90 min | Practice it hands-on | Review · demo · hands-on lab · guided practice · reflection |
| **Day 3 — Create** | 90 min | Apply it to something real | Real-world challenge · build · testing · peer feedback · revision · submission |

## Week 1 — The Problem Solving Process

**Driving Question:** What common steps can we use to solve many different kinds of problems?

**Big Idea:** Good problem solvers follow a process — Define, Prepare, Try, Reflect (DPTR) — that works whether you're seating birthday guests or building an app.

| Day | Focus | Key Activities |
|-----|-------|----------------|
| **Day 1 — Learn** | The DPTR cycle | Journal hook ("a problem you're good at solving") → mini-lesson on the 4 steps → watch Code.org "Problem Solving Process with Zipline" video → map your own process to DPTR → exit ticket |
| **Day 2 — Explore** | Practicing the process | Word Search (warm-up) → **Birthday Guests** constraint puzzle (the core DPTR lab) → guided debrief mapping each move to Define/Prepare/Try/Reflect |
| **Day 3 — Create** | Applying the process | **Redesign Your Classroom** challenge: set goals → design a layout → peer feedback → revise & finalize → reflection table (how each step used DPTR) |

**Week 1 Deliverable:** Completed Problem Solving Process Notes (the DPTR reflection table + purpose-of-each-step definitions).

### MS vs HS differentiation (Week 1)
- **MS:** More scaffolding on the Birthday Guests puzzle (hint cards, sentence starters for reflection). Redesign is a drawing/description.
- **HS:** Birthday Guests framed as a *constraints optimization* problem (introduce the vocabulary: constraints, trade-offs, "good enough" vs. optimal). Reflection asks students to articulate *why* the process generalizes, and to identify where a computer could automate parts of it.

## Week 2 — What Is a Computer? (IOSP) + App Design Project

**Driving Question:** How can the Input–Output–Storage–Processing model help us design an app that solves a problem?

**Big Idea:** Every computer — and every app — works by taking **Input**, doing **Processing**, using **Storage**, and giving **Output** (IOSP). You can use this model plus the DPTR process to design a solution to a real problem.

| Day | Focus | Key Activities |
|-----|-------|----------------|
| **Day 1 — Learn** | What makes a computer a computer | Hook ("what made computers different?") → vocabulary: Input, Output, Processing, Storage → Code.org videos "How Computers Work: Hardware & Software" and "What Makes a Computer, a Computer?" → four kinds of processing (If/Then, Comparing, Finding a Match, Counting) → smartphone IOSP breakdown → exit ticket |
| **Day 2 — Explore** | IOSP in real devices + launch the project | IOSP labeling lab (analyze real apps/devices) → launch **Apps & Problem Solving** project → Define the problem (partner work) → begin IOSP design |
| **Day 3 — Create** | Build & present the app design | **MS:** finish IOSP design → app sketch → poster → gallery walk. **HS:** build a working HTML/JS prototype of the app (real Input→Process→Output page) in StackBlitz → peer review → present |

**Week 2 Deliverable:**
- **MS:** Completed Project Guide + app poster + presentation.
- **HS:** Working app prototype (HTML/JS) + Project Guide + presentation.

### MS vs HS differentiation (Week 2)
- **MS:** The app stays a *paper/poster design* (exactly like the Code.org Lesson 8 project). IOSP is a planning tool. `self-study.html` has no code editor — it uses interactive IOSP labeling + reflection.
- **HS:** The app becomes a *real prototype*. IOSP becomes a coding spec (inputs = form fields, processing = JS logic or an AI API call, output = rendered result). `self-study.html` (HS only) embeds a **StackBlitz** editor for the build.
