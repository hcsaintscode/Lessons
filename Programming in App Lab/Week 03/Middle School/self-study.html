Lesson 1

Reading Input & Strings

An app can't decide anything until it reads what you gave it. When you type in a box or pick from a menu, the app reads that value with something like .value — grabbing whatever's currently in the field.

Text in code is called a string. A string is any run of characters wrapped in quotes, like "popcorn" or "Try ". You can glue strings together with + — that's called concatenation.

Read Input — grab the value

var name = document.getElementById("nameInput").value; reads whatever's typed in the box into a variable.

Build a String — glue text together

+ joins strings. "Hi " + name makes one new string out of two pieces.

Show It — put it on screen

Set the built string as an element's .textContent so the user can read it.

Combine a name into a greeting
var name = "Jordan";
var greeting = "Hi " + name + ", welcome!";
// greeting is now: "Hi Jordan, welcome!"

Notice the space inside the quotes: "Hi ". If you leave it out, you get "HiJordan" squished together — the space has to be inside the string.

Lesson 2

Making Decisions (if / if-else)

An if statement runs a block of code only when a condition is true. Add an else and you get two paths: one when the condition is true, another when it's false. Chain them with else if to check several options in a row.

To compare two values, use == (or ===) — for example craving == "sweet" asks "are these the same?" A single = is different: it assigns a value into a variable.

Watch out — == compares, = assigns
if (craving == "sweet") { ... }   // CORRECT: compares
if (craving = "sweet") { ... }    // BUG: this ASSIGNS, not compares

That single-= line doesn't ask a question at all — it jams "sweet" into craving and then always runs. Use == (or ===) whenever you're checking a condition.

Make It Yours

Make It Yours

Now change the code on the right so the Snack Picker suggests your favorites and knows your cravings. You decide what it offers:

  • Change a suggestion: edit one of the snack = "..." lines to a snack you actually like.
  • Add an option: add a NEW choice to the dropdown in index.html AND a matching else if branch in index.js.
  • Stretch: change the greeting string so it sounds like you — like "Yo " + name + ", grab ".
Stuck? example edit

Add a new spicy option to the dropdown in index.html:

<option value="spicy">Spicy</option>

Then add a matching branch in index.js, before the final else:

} else if (craving === "spicy") {
  snack = "spicy trail mix 🌶️";
}

New option in, matching branch to handle it — now the app can decide about spicy too.

Reflect

Decisions in Your Life

You make dozens of small choices every day, and most of them follow rules — if it's raining, then grab a hoodie; if you're tired, then pick an easy show. That's exactly how an app decides: read the input, then follow the rules.

Wrap-Up

The Big Idea

Apps feel smart because they read your input and use conditionals to choose what to do. Different input → different output. Read the value, compare it with ==, and let if / else if / else pick the path. That's the pattern behind every app that responds to you.
