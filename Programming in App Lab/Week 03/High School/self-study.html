Lesson 1

Boolean Expressions

Before code can choose, it has to ask a yes/no question. A boolean expression is any expression that evaluates to exactly one of two values: true or false. That single true/false answer is what a decision hangs on.

You build boolean expressions with comparison operators: == (equal to), != (not equal), > (greater than), < (less than), >= (greater or equal), <= (less or equal). The classic trap: == compares two values and gives back true/false, while a single = assigns — it stores a value into a variable. They look alike but do completely different jobs.

Read Input — get a value to test

Pull a value from the user or a variable — a genre, a number of minutes, a checkbox. That's the raw material your condition will judge.

Test a Condition — ask a true/false question

minutes < 45 or genre == "comedy" each evaluate to true or false. That's a boolean expression.

Branch — act on the answer

Feed the true/false into an if so the program runs one block when it's true and skips it when it's false.

A boolean expression evaluates to true or false. Use == to compare and = to assign — mixing them up is the most common beginner bug.

Lesson 2

if-else-if & Compound Conditions

One if handles a single yes/no. To pick among many outcomes, you chain them: if … else if … else. The program checks each condition top-to-bottom and runs only the FIRST branch that's true — then it skips the rest of the chain entirely.

Because only the first true branch wins, order matters. Put your specific conditions before your general ones. If a broad condition sits on top, a more specific branch below it becomes unreachable — the code is there, but it can never run.

Compound conditions combine several tests into one using logical operators:

  • && (and) — true only when both sides are true.
  • || (or) — true when either side is true.
  • ! (not) — flips true to false and false to true.

The recommender on the right uses an if-else-if chain with a compound condition — watch which single branch wins for each combination of inputs.

Compound condition example
if (minutes < 30 && withFriends) {
  pick = "one short clip to watch together";
}

Read it as: run this branch only when the time is short AND you're watching with friends. Both must be true.

Make It Yours

Make It Yours

Now make the recommender yours. Base it on how you actually pick something to watch — your favorite genres, your real time limits, the people you watch with:

  • Change one recommendation: rewrite a pick = "…" string so it names a show or movie you'd actually recommend.
  • Add a new genre: add an <option> to the dropdown in index.html and a matching else if branch in index.js so it has a real recommendation.
  • Stretch: add a compound condition of your own — for example, short time && with friends → a specific pick. This is a decision rule you invented.
Stuck? Example edit

Add a new else if branch that uses a compound condition. Place it high in the chain (before the general else) so it can actually be reached:

} else if (genre === "action" && minutes >= 120) {
  // compound: BOTH must be true -- action AND lots of time
  pick = "an epic action movie with a long runtime";
} else if (genre === "comedy" || withFriends) {
  // compound: EITHER one being true is enough
  pick = "an easy crowd-pleaser";
}

Order it carefully: this specific action branch has to sit above any general "action" branch, or it becomes unreachable and never runs.

Reflect

Logic & Directing AI

When you direct an AI to build an app, you won't just say "make it decide" — you'll describe the rules: which conditions lead to which outcomes, and where two things have to be true at once. Knowing how if-else-if chains and compound conditions work means you can state those rules clearly, and you can catch it when the AI puts a branch in the wrong order or writes one that can never run.

Wrap-Up

The Big Idea

Conditional logic is how software chooses. Master if-else-if and compound conditions and you can express — and audit — almost any decision rule. Get the order or the operators wrong and you get the classic bugs: the wrong recommendation, or a branch that can never run.
