Lesson 1

Functions & Parameters

A function packages a piece of behavior under a name so you can reuse it whenever you want — write it once, run it as many times as you like. Instead of copying the same lines over and over, you call the function by name.

A parameter is an input a function accepts — a placeholder that lets one function vary its behavior. When you call the function, you hand it an argument (the actual value), and the parameter takes that value for that run. One function, many outcomes, depending on what you pass in.

Define — write it once, with a parameter

function addScore(points) { … } names the behavior and declares a parameter points — the input that will vary.

Call — pass an argument

addScore(10) runs the function with points set to 10. Call addScore(5) and the same function does the job with a different value.

Reuse — one function, many cases

Because the value comes in through the parameter, you never rewrite the function. Change the argument, not the code.

A function is reusable named behavior. A parameter is the input that lets one function handle many cases — pass a different argument and you get a different result, no rewrite needed.

A tiny parameterized function
function greet(name) {   // name is the PARAMETER
  return "Hi, " + name + "!";
}
greet("Sam");            // "Sam" is the ARGUMENT -> "Hi, Sam!"
greet("Alex");           // same function, different result
Lesson 2

Decomposition

Decomposition is breaking a big app into small, single-purpose functions — one job each. Instead of one giant blob of code that does everything, you get a set of clearly named pieces: one makes a target, one checks a guess, one resets the game. Each piece is short enough to understand at a glance.

This is how real software stays readable and debuggable. When something breaks, you don't hunt through hundreds of tangled lines — you look at the one function whose job that is. And when you want to change behavior, you change one small piece without touching the rest.

The Color Match game on the right is decomposed into makeTarget() and checkGuess(id) — each does one job. One makes a random target; the other checks a guess and updates the score.

Run It

Run the Color Match Game

The editor on the right is running a Color Match Game — a small but complete app that pulls together everything you've learned:

  • A function makeTarget() picks a random target color and shows it.
  • A parameterized function checkGuess(guess, points) checks your click and adds points to the score.
  • An event on each swatch button calls checkGuess — plus a variable for the score and a conditional to decide right vs. wrong.

Click Run (or refresh the preview), then play: a target color appears, you click the matching swatch, a parameterized function updates the score, and a new target is made. Get a few right and watch the score climb.

Make It Yours

Make It Yours

Now make the game yours. Pick colors you actually like, tune the scoring the way you think it should work, and add a piece of your own:

  • Add another color: add a new <button class="swatch"> (with a data-color and background) in index.html and add that color to the colors array in index.js.
  • Change the points: a correct guess passes 10 as the argument to checkGuess. Change that number and see the score jump by your amount — you're changing the argument, not the function.
  • Stretch: write a brand-new function of your own (one job each) — e.g. resetGame() that sets the score back to 0 — and call it from a button you add.
Stuck? Example edit

Add a color to the colors array (and a matching button in index.html), then write your own single-job function and wire it to a button:

// in index.js -- add a fifth color
var colors = ["#e8553d", "#2bb5a0", "#2d1b69", "#f4c430", "#5b8def"];

// your OWN function -- one job: reset the game
function resetGame() {
  score = 0;
  document.getElementById("score").textContent = score;
  makeTarget();
}

// wire it to a button (add <button id="resetBtn">Reset</button> in index.html)
document.getElementById("resetBtn").addEventListener("click", resetGame);

Notice resetGame() does exactly one job and even reuses makeTarget() — that's decomposition in action.
