Functions & a Real App

Week 4 — Package code into functions, build a full app, and connect to AI builders

At a Glance

Driving Question
How do you package code to reuse it — and put everything together into a real app?
Big Idea
A function is a named recipe you define once and call anytime. Combined with events, variables, and conditionals, functions let you build a complete app. And because you can read code, you can now direct and debug AI app builders too.
Schedule
Day 1 Learn (45 min) · Day 2 Explore (90 min) · Day 3 Create (90 min)
Week Deliverable
A self-chosen app using events + a variable + a decision + at least one function — shared via link — plus a reflection connecting coding to directing an AI builder

Learning Objectives

Students will be able to:

  • Define a function and call it by name to reuse code
  • Use randomness (randomNumber) to make an app dynamic
  • Combine events, variables, conditionals, and functions into a complete app
  • Explain how understanding code helps you direct and debug an AI app builder

Day 1 — Learn: Functions — Reusable Recipes

Define once, call anytime

Time Activity
0–8 min Hook — recap the journey (events → variables → conditionals → functions)
8–24 min Mini-lesson — what a function is; define vs. call; randomness
24–38 min Write & call a function together in App Lab
38–42 min App Lab lesson pointer (Code.org Lessons 10–11)
42–45 min Exit ticket

Hook (8 min)

"Look how far you've come: Week 1 your apps reacted (events), Week 2 they remembered (variables), Week 3 they decided (conditionals). This week you learn FUNCTIONS — reusable recipes — and put it ALL together into a real app."

Put the four words on the board as a timeline: events → variables → conditionals → functions. Students should feel the momentum — they already know three of the four building blocks. Today's word is the last one, and then everything snaps together into a whole app.

Mini-lesson: What a Function Is (16 min)

"A function is a set of steps you write once, give a name, and then run whenever you want just by saying its name. You DEFINE it once, and you CALL it as many times as you like. And a special block, randomNumber, gives you an unpredictable value — perfect for games."

  • FUNCTION — a named block of code you define once and reuse anywhere in your app.
  • DEFINE — write the recipe: function updateScore() { ... }
  • CALL — run it by name: updateScore();
  • RANDOMNESS — randomNumber(0,255) gives an unpredictable value — great for games.

"Defining a function doesn't run it — it just teaches the app the recipe. The steps only happen when you CALL the function by name. So we write the recipe once at the top, then call it from an event down below."

function updateScore() { score = score + 1; setText("scoreLabel", score); } onEvent("goBtn", "click", function() { updateScore(); });

A function is like a recipe card — write the steps once, then just say "make it" whenever. It means less repeated code and one place to fix things. If you ever need to change how the score updates, you edit the recipe once and every call gets the fix automatically.

studio.code.org/courses/csp5-virtual/units/1 — Lesson 10 Color Sleuth, Lesson 11 Keep Going

Write & Call a Function — Together (14 min)

"Let's build one together. We'll define a tiny function that shows a friendly message, then call it from a button click. Watch how the recipe sits up top and the button just says its name."

function greetUser() { setText("messageLabel", "You clicked the button!"); } onEvent("helloBtn", "click", function() { greetUser(); });
  • Have every student add one button and one label to their screen, then type the function definition first.
  • Point out the empty greetUser() call inside the event — that's where the recipe gets used.
  • Ask them to add a second button that calls the SAME function — proof that one recipe can be reused.
  • Have a few students add randomNumber(1,6) inside the function to show a random "dice roll" in the label.

What's the difference between DEFINING a function and CALLING it? Why are functions useful?

Every student defined a function and called it from an event.

Day 2 — Explore: Build Color Sleuth (Everything Together)

Events + variables + conditionals + functions in one app

Time Activity
0–5 min Review — define vs. call
5–20 min How Color Sleuth works — demo + RGB / random color
20–70 min Build Color Sleuth (guided)
70–85 min Test + debug
85–90 min Record vocab + checkpoint

Review (5 min)

"Quick recall: to DEFINE a function is to write the recipe; to CALL it is to run it by name. Today we use functions to build a real game — Color Sleuth — that pulls together everything from the whole unit."

How Color Sleuth Works (15 min)

"The app shows several color buttons. One is slightly different from the rest. The app picks a random target color with a function. Click the right button and your score (a variable) goes up and it's the next player's turn. Click a wrong one and a conditional handles it — no points. It uses events, a variable, a conditional, AND a function, all at once."

Colors in App Lab are written as rgb(red, green, blue), where each number is 0–255. That's why randomNumber(0,255) is perfect here — it picks a random color channel so the target color is different every round. You don't need to memorize this; just show it once on the projector.

function makeRandomColor() { var r = randomNumber(0, 255); var g = randomNumber(0, 255); var b = randomNumber(0, 255); return "rgb(" + r + "," + g + "," + b + ")"; } function pickTarget() { var color = makeRandomColor(); setProperty("button1", "background-color", color); }

Build Color Sleuth — Guided (50 min)

"App Lab Lesson 10 gives you the structure to build on. As you go, keep pointing to the four building blocks: find the FUNCTION, find the VARIABLE (score), find the EVENTS (button clicks), and find the CONDITIONAL (right button vs. wrong button)."

  • Keep scope to a working core: pick a target, click a button, move the score up or down.
  • Use console.log to see the target color and confirm which button was clicked.
  • Declare score outside the handlers so it survives between clicks (Week 2 callback).
  • Make sure functions are defined ABOVE the code that calls them.
  • Help students match element IDs exactly — button1 in the design must match button1 in the code.
var score = 0; onEvent("button1", "click", function() { if (isCorrect("button1")) { score = score + 1; } else { score = score - 1; } setText("scoreLabel", "Score: " + score); });

The classic bug is calling a function that isn't defined yet, or a typo in the function name — the app just "does nothing." No error pops up, it simply doesn't run. Check that the name in the call matches the name in the definition EXACTLY, including capital letters.

Record Vocab (5 min)

  • function — a named, reusable recipe
  • define — write the recipe once
  • call — run the recipe by name
  • randomNumber — get an unpredictable value
  • setProperty — change a property like a button's color

Every student has a working Color-Sleuth-style app (or a scoped version) using a function + variable + event + conditional.

Day 3 — Create: Your Capstone App + the AI Bridge

Build something yours — then see how it connects to AI builders

Time Activity
0–5 min Launch — the capstone challenge
5–20 min Plan your app — make it yours
20–65 min Build in App Lab
65–78 min Showcase & share
78–90 min The AI bridge + reflection

Launch (5 min)

"Your capstone: build a small app that's YOURS — a mini game, a helper, a quiz, a tracker — using an event, a variable, a decision, and at least one function. Pick something you'd actually use or share."

Make It Yours: Plan Your App (15 min)

"Before you touch the code, plan on paper. What does your app do? What event or events will it react to? What variable will it remember? What decision (conditional) will it make? And what function will you write and call?"

  • What does it do, and who is it for? (Pick something from YOUR world — a hobby, your team, a subject, a joke you like.)
  • What event(s) will it respond to? (a button click, a key press)
  • What variable will it track? (a score, a count, a name)
  • What decision will it make? (right vs. wrong, high vs. low, yes vs. no)
  • What function will you define and call? (name it something clear like nextQuestion or rollDice)

Ideas to spark choices without assigning one: a two-question quiz about their favorite show, a "should I?" random decider, a click-counter for push-ups, a reaction-time game, a compliment generator for a friend. The point is that they choose — the requirements (event + variable + decision + function) stay the same.

Build (45 min)

  • Small and working beats big and broken — get one thing working, then add.
  • Write one function and call it; that satisfies the requirement even if it's short.
  • Test after each step so a bug is easy to find.
  • Reuse everything from Weeks 1–3: events, variables, strings, and conditionals.

Extend Beyond the Classroom: Showcase & Share (13 min)

"Share the App Lab link so your app lives on. Demo it to the class or a partner, and point to the event, the variable, the decision, and the function inside it. Then share the link with a friend or someone at home and let them try it."

  • Use App Lab's Share button to get a keepable link.
  • Have each student point to all four building blocks in their own code as they demo.
  • Encourage sharing the link with a friend or family member to try at home.

The AI Bridge (part of 78–90 min)

"Soon you'll use AI tools that BUILD an app from a description (like Lovable, in your other unit). Because you now understand events, variables, conditionals, and functions, you can (1) TELL the AI exactly what app to build, and (2) READ what it makes, spot bugs, and fix them or tell it precisely what to change. Understanding code gives you control."

  1. How would you describe your capstone app to an AI builder so it builds the right thing?
  2. If the AI's app had a button that did nothing, what would you check first?
  3. What can you do now that you couldn't before this unit?

Reflection

  • What does your app do, and why did you build THIS one?
  • Point to the event, the variable, the decision, and the function in your code.
  • How does knowing this code help you work WITH an AI app builder?

Additional Notes

Differentiation

  • Support — give a starter project with one function already stubbed in; let students personalize a scoped Color Sleuth instead of building a brand-new app; provide sentence frames for the reflection.
  • Advanced — encourage multiple functions, functions that take parameters, a two-player mode, or a harder random challenge (tighter color differences, a timer, levels).

For the Non-Technical Teacher

  • The one bug to know: a function must be DEFINED (and spelled the same, capital letters included) before it's CALLED, or the app simply does nothing.
  • This is the last big concept of the unit — celebrate loudly. Students can now build a whole app from scratch.

Connecting the Arc — the Lovable bridge

  • This unit ends by handing off to the Problem Solving & Computing capstone, where students build apps with lovable.dev.
  • The point: knowing how events, variables, conditionals, and functions work lets students DIRECT the AI precisely and DEBUG what it generates, instead of accepting it blindly.
