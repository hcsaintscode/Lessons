Reference

Key Vocabulary

  • Event-Driven ProgrammingCode organized as handlers that run in response to events — not just top-to-bottom, start-to-finish.
  • EventSomething the user does — a click, a keypress, typing into an input.
  • Event Handler / CallbackA function that runs later, when its event fires.
  • onEventApp LabonEvent(id, type, function) wires an element to a handler.
  • PropertyAn element feature you can read or set — text, color, image.
  • setText / setPropertyFunctions that change an element's output on the screen.
  • console.logPrints a value so you can inspect it while debugging.

Anatomy of a Handler

Read this handler line by line, then answer the questions. Every interactive app is built from patterns exactly like this one.

Same Idea

App Lab vs Plain JS

One concept, two syntaxes App Lab's onEvent is a friendlier wrapper around the same event-driven idea you'll see everywhere in real JavaScript. The wiring looks different; the concept is identical.
App Lab: onEvent("btn", "click", function() { ... }); Plain JS: btn.addEventListener("click", function() { ... });
In your own words, why are these “the same idea”?
Debug It

Debugging Drill

This handler is supposed to change a label to “Go!” when a button is clicked — but nothing happens. The element in Design Mode has the id startBtn and the label has the id status.

onEvent("startbtn", "click", function() { setText("Status", "Go!"); });
This handler does nothing when clicked. Find TWO likely bugs. Look carefully at every id — capitalization matters.
How would console.log help you confirm the handler even runs?
