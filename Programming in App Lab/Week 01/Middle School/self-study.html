Lesson 1

What Is an Event?

An event is something the user does — a tap, a click, a swipe, a key press. When the event happens, your app runs a special chunk of code called an event handler in response. That's how apps feel alive: they wait, you act, they react.

It's the IOSP pattern, live: the click is the input, the handler is the processing, and the change you see on screen is the output.

Event — the click (input)

The user clicks a button. Nothing happens yet — the app has just noticed something happened.

Handler — the code that runs (processing)

The event handler wakes up and decides what to do. It's the code you wrote for "when this is clicked, do this."

Change — what you see (output)

The handler changes the page: new text, a new color, a sound. That visible change is the output the user actually experiences.

Every interactive app is this loop: the user does something, your handler runs, the screen changes.

Lesson 2

Reading a Click Handler

A click handler always has the same shape: name the button, name the event ("click"), and give it a function — the code to run. Here's the same idea two ways:

App Lab style
onEvent("button1", "click", function() {
  // this code runs when button1 is clicked
});
Plain JS (what's in the editor →)
button.addEventListener("click", function() {
  // this code runs when the button is clicked
});

Different words, exact same idea: "when this button is clicked, run this function." App Lab's onEvent and the browser's addEventListener are two ways of saying the same thing. Learn one and you can read the other.

Make It Yours

Make It Yours

Now change the code on the right so the button reacts your way. You decide what it says and how it looks:

  • Change the message: edit the text in heading.textContent so the button says something you'd say.
  • Change the color: edit the document.body.style.background color to your favorite one.
  • Stretch: add a second button that does something different — maybe it changes the text to a different message or a different color.
Stuck? Example edit

Change what the heading says by editing the text string in index.js:

heading.textContent = "Nice tap! You got this \uD83D\uDE0E";
document.body.style.background = "#fff3d6";

Add a second button with its own handler. First add it to index.html:

<button id="resetBtn">Reset</button>

Then give it its own addEventListener in index.js:

var resetBtn = document.getElementById("resetBtn");
resetBtn.addEventListener("click", function () {
  heading.textContent = "Click the button!";
  document.body.style.background = "#ffffff";
});

Two buttons, two handlers — each reacts to its own click.

Reflect

Events in Your Life

You trigger event handlers all day without thinking about it. Every time you tap "like," send a message, add something to a cart, or hit play, a button fires an event and some handler code runs to change what you see.

You made a screen react — in code! 🎉

You learned that events are things the user does, and handlers are the code that reacts. You ran a real click handler, changed it to make it yours, and connected it to apps you use every day. Next week (Week 2) you'll meet variables — how apps remember things, like a score that keeps counting up.

Wrap-Up

The Big Idea

Interactive apps are just events + handlers: the user does something, your code reacts. That's the heart of every app — every like button, every game control, every menu. You just wrote one yourself.

Next week, you'll add variables so your app can remember — turning a one-shot reaction into something that keeps track, like a counter or a score.
