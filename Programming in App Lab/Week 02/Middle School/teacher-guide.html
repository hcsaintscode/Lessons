Variables & State: Apps That Remember

Week 2 — Store and change values, then build a Clicker Game

At a Glance

Driving Question
How does an app remember and change a value — like a score that goes up?
Big Idea
A variable is a labeled box that stores a value. Events change the value; the screen shows it. Variables + events = an app with state.
Schedule
Day 1 Learn (45 min) · Day 2 Explore (90 min) · Day 3 Create (90 min)
Week Deliverable
A working counter/Clicker app that updates a variable on clicks and displays it — shared via link

Learning Objectives

Students will be able to:

  • Explain what a variable is using the labeled-box mental model
  • Declare, assign, and update a variable in App Lab
  • Combine a variable with a click event to track state (a score/count)
  • Use console.log to check a variable's value while debugging

Day 1 — Learn: What Is a Variable?

The labeled-box mental model

Time Activity
0–8 min Hook — "How does a game remember your score?"
8–24 min Mini-lesson — variable = labeled box; declare / assign / update; showing it on screen
24–38 min Your first variable, together in App Lab
38–42 min App Lab lesson pointer (Code.org Lessons 3, 4 & 5)
42–45 min Exit ticket

Hook (8 min)

"A video game shows your score going up as you play. Somewhere the app is REMEMBERING that number and changing it. How? With a variable — a labeled box that holds a value the app can read and change."

Take a few quick answers out loud. Some students will guess "it just saves it somewhere" — that's exactly right, and the "somewhere" has a name: a variable. Keep the image of a box with a label on it in everyone's head.

Mini-lesson: Variable = A Labeled Box (16 min)

"Last week our apps could react to a click, but they forgot everything the instant it was over. Today we give apps a memory. The tool for memory is a variable — and there are exactly three things you do with one."

  • VARIABLE — a named box that stores a value the app can remember and change (a score, a count, a name).
  • DECLARE — make the box and give it a label: var score;
  • ASSIGN — put a value in the box: score = 0;
  • UPDATE — change what's in the box: score = score + 1;

"Picture a shoebox with a label that says SCORE. Declaring is grabbing the box and writing the label. Assigning is dropping a value inside. Reading is peeking in to see what's there. Updating is taking it out, changing it, and putting it back. That's the whole idea — a labeled box you can put a value in, read, and replace."

var score = 0; setText("scoreLabel", score); score = score + 1; setText("scoreLabel", score);

The trickiest idea for beginners is score = score + 1 — it means "take what's in the box, add 1, put it back." Read it right-to-left: figure out the right side first, then store the result back in the box on the left.

Your First Variable — Together (14 min)

"Everyone open App Lab. In Design Mode, drag a label onto the screen and rename its id to scoreLabel. Now switch to Code. We'll make a box called score, put 0 in it, show it on the label, then add 1 and show it again. Watch the label change."

  • Have everyone type the four lines above, one at a time, and run after each line so they SEE the label update.
  • Ask: "What number shows first? What shows after the last line?" (0, then 1.)
  • If the label doesn't change, check that the id on screen matches scoreLabel exactly.

You don't need to write any of this from memory. App Lab has a "Show value" / drag blocks helper, and you can keep this guide open. Your job is to keep the labeled-box picture front and center.

Day 2 — Explore: Variables + Events = State (The Clicker Game)

A button that changes a value — and debugging with console.log

Time Activity
0–5 min Review — declare / assign / update
5–15 min Connect variables to Week 1 events
15–55 min Build the Clicker Game (button increments score, displays it)
55–75 min Debugging with console.log
75–90 min Progress check + vocab

Review (5 min)

"Quick recall. What are the three things you do with a variable? Declare — make the labeled box. Assign — put a value in. Update — change it. And what did we learn last week that makes apps react to a click? The onEvent handler. Hold onto both — today we combine them."

Connect: The Magic Is Combining Them (10 min)

"On its own, a variable just sits there. On its own, a click just fires once and forgets. But put a variable UPDATE inside a click handler, and every click changes the box. Now the app remembers something between clicks. That memory has a name: STATE."

  • STATE — the value an app is currently holding onto (the score right now). It carries from one click to the next.

Say it plainly: a click event that updates a variable is the whole recipe for an app that remembers. Everything from here — high scores, likes, levels — is a version of this.

Build the Clicker Game (40 min)

"In Design Mode, add a button with id clickBtn and a label with id scoreLabel. Then in Code, we declare score ONCE at the top, and inside the click handler we add 1 and show it. Let's build it."

var score = 0; onEvent("clickBtn", "click", function() { score = score + 1; setText("scoreLabel", score); });
  • Every student gets a button that increments a score and shows it on the label.
  • Watch for the classic bug: declaring var score = 0 INSIDE the handler resets it to 0 every click — it must be declared OUTSIDE, at the top.
  • Encourage a reset button as a stretch: a second button that sets score = 0 and updates the label.

Debugging with console.log (20 min)

"When a number looks wrong, don't guess — LOOK. console.log("score is", score) prints the value into the console so you can SEE exactly what the app is actually holding right now. Add it inside your handler and watch it count up as you click."

onEvent("clickBtn", "click", function() { score = score + 1; console.log("score is", score); setText("scoreLabel", score); });

The #1 variable bug is declaring the variable INSIDE the event handler, so it resets to 0 on every click. Declare it once, OUTSIDE the handler, at the top of your program. If console.log keeps printing "score is 1," this is why.

Progress Check + Vocab (15 min)

Record this week's vocabulary in the worksheet:

  • variable — a labeled box that stores a value
  • declare — make the box (var score;)
  • assign — put a value in (score = 0;)
  • update — change the value (score = score + 1;)
  • state — what the app is remembering right now
  • console.log — print a value to check it while debugging

Every student has a working Clicker (click increments a variable and updates the display) and used console.log at least once.

Day 3 — Create: Build Your Own Tracker

A counter for something YOU care about

Time Activity
0–5 min Launch — turn the Clicker into a personal tracker
5–20 min Plan your tracker
20–70 min Build in App Lab
70–82 min Share & test
82–90 min Reflection

Launch (5 min)

"Turn the Clicker into a tracker for something in YOUR life — glasses of water, push-ups, pages read, chores done, hype level. A button adds to a count; maybe a button that resets or subtracts. You pick what it counts, because it's yours."

Make It Yours: Plan Your Tracker (15 min)

"Before you touch code, decide three things. This is the part that makes it YOUR app, not everyone's identical clicker."

  • What are you counting, and why does it matter to you?
  • What does each button do — add, reset, or maybe subtract?
  • What does the label show, and what should it say to start?

There's no single "right" tracker here. Water, reading minutes, free throws made, kind things done today — if a student cares about it and it counts, it works. Let them choose.

Build in App Lab (50 min)

"Start from your Clicker code and rename the variable and label to fit your idea — like waterCount and countLabel. Add your buttons and wire each one up. Test after every change."

  • Declare the variable OUTSIDE the handler, at the top — the one bug that resets everything.
  • Test after each change so a bug is easy to find while it's small.
  • Add a reset button (count = 0; then update the label) so the tracker can start a new day.
  • If the number looks wrong, drop in a console.log to see what the box actually holds.

Extend Beyond the Classroom: Share & Test (12 min)

"Use App Lab's Share button to get a link — that link is yours to keep. Hand it to a partner and have them test it. Then actually USE your tracker at home for a day and see if it's helpful in real life."

  • Have each student generate and save their App Lab share link (a keepable artifact they can reuse).
  • Partner test: does the count go up? does reset work? does the label match?
  • Home challenge: run it for one day and notice whether it changed anything.

Reflection (8 min)

  • What are you tracking, and why does it matter to you?
  • Where's the variable, the event, and the output in your app?
  • What would make your tracker more useful in your own life?

Additional Notes

Differentiation

  • Support — hand out a starter with the variable already declared and the label wired, so the student just adds the + 1; or a fill-in-the-blank handler with gaps to complete.
  • Advanced — add reset and subtract buttons, a second variable (like a goal to reach), or change the label's color when the goal is hit.

For the Non-Technical Teacher

  • The one bug to know cold: the variable must be declared OUTSIDE the event handler, or it resets every click. If a number is stuck at 1, this is almost always why.
  • Reading score = score + 1 right-to-left helps students — figure out the right side, then store it back in the box.

Connecting the Arc

  • Variables give apps memory (state) — this is the S in IOSP (storage) at the code level, and it's what lets an app track anything.
  • It also sets up directing an AI builder: you'll be able to specify exactly what the app should remember.
